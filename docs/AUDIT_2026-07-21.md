## TIER 1 — Self-confirming loops & authoritative-record integrity (highest stakes)

### L1 — Prediction correctness is graded against the same LLM signal that produced the prediction — and the loop still runs live
**Classification: FACT.  Verify: ✓**

`memory/prediction_tracker.py:34-43` (`make_prediction`) records the prediction value as
the axis's current web-intel **`urgency`**. `memory/prediction_tracker.py:70-73`
(`verify_and_learn`) then sets `was_correct = (current urgency == predicted urgency)`:

- `memory/prediction_tracker.py:70` — `actual = current_axes[axis].get("urgency", "LOW")`
- `memory/prediction_tracker.py:71` — `was_correct = actual == p["predicted_urgency"]`

`urgency` is an LLM output, not an authoritative outcome
(`agents/internet/internet_agent.py:990,1053` — the LLM is *asked* to emit an
`urgency` field). So `was_correct` measures LLM self-consistency, not reality.

**The loop is still executing every cycle**, from *two* live call sites:
- `core/cortex_orchestrator.py:299` `verify_and_learn(axes_data)` then `:302`
  `make_prediction(ax, ..., axes_data[ax].get("urgency","LOW"))` — same `axes_data`
  object shapes and checks. Orchestrator is wired live at `fast_cycle_runner.py:886-888`.
- `agents/core/feedback_loop.py:137-142` — a second independent live caller of
  `make_prediction`.

**Proposed fix (Phase 2, not applied):** stop calling `verify_and_learn`/`make_prediction`
from `cortex_orchestrator.py:297-302` and `feedback_loop.py:135-142`; route axis
self-prediction exclusively through the sealed prophecy path (see L2). FACT-class:
removes a live self-confirming loop the repo already declared dead.

### L2 — The sealed, authoritative K1a replacement is NOT wired into the cycle; only the quarantined loop runs
**Classification: FACT.  Verify: ✓**

`memory/prediction_tracker.py:7-17` declares itself `QUARANTINED — NON-AUTHORITATIVE`
and names the authoritative replacement: the sealed prophecy path
(`experiments/prophecy/prophecy.py`, `target_kind='axis_next'`). That path exists —
`experiments/prophecy/prophecy.py:161` `def seal_axis_prediction(...)`, `:206`
scores matured predictions against the next observed score (tamper-evident, chained
in `experiments/prophecy/prophecy_ledger.py:29`).

**But a repo-wide grep shows `seal_axis_prediction` / `axis_next` is called from
nowhere in the live cycle** — only inside `experiments/prophecy/` itself and in
`prediction_tracker.py`'s quarantine docstring. Meanwhile the quarantined loop (L1) is
live. Net effect: the *label* says "superseded"; the *code* still runs the superseded
path and never runs the replacement.

**Proposed fix (Phase 2):** wire `prophecy.py --predict-axes` (or `seal_axis_prediction`)
as a per-cycle step in `fast_cycle_runner.py`, paired with removing the L1 call sites.
FACT-class wiring; the target module already exists and is tested
(`test/test_axis_prediction_sealing.py`).

### L3 — CORRELATION_MATRIX both shapes the published scores AND is the declared basis for the audit that checks them
**Classification: FACT (architecture) + JUDGMENT (coefficient values).  Verify: ✓**

- **Shapes:** `cortex_scoring_engine.py:1256-1269` defines `CORRELATION_MATRIX`;
  `apply_correlations()` (`:1272`) mutates scores by it and writes them back —
  `:1293` `scores[axis].score = round(new_score, 2)`; called at `:1497`
  `scores = apply_correlations(scores)` inside `score_all_snapshots`, persisted to
  `output/cortex_scores_latest.json` (`:1565`). Runs every cycle via
  `fast_cycle_runner.py:796`.
- **Checks:** `experiments/symbolic_duel/metta_reason_live.py:24-25` states the
  cross-axis audit rulebook is to be *"grounded in
  cortex_scoring_engine.CORRELATION_MATRIX + domain logic,"* and `:54` flags an axis
  when the rules imply a higher concern than the score shows.

Today this loop is **declared, not fully closed**: the audit's live `RULES`
(`metta_reason_live.py:26-33`) are a hand-authored seed set, not literally imported
from `CORRELATION_MATRIX`. **Closing it** (deriving the rulebook from the matrix, as
line 25 instructs — the exact task this audit interrupted) would make the same
AI-asserted model both produce and grade the scores. The 12 coefficients themselves are
hand-set (see L7) → JUDGMENT.

### L8 — target_config.json: target VALUES mostly anchored; WEIGHTS and qualitative axes are asserted

  hand-ranked, no derivation.
- Several axes have `primary_metric: None` / `target_value: None` (CULTURE_MEDIA,
  TECHNOLOGY_AI, TECHNOLOGY_INFRA, COSMIC_RESOURCES, DEEP_TIME_RISKS, etc.) → scored
  qualitatively (routes to `score_generic`, L6).
- MATERIALS_WASTE reuses `co2_ppm_mauna_loa` as a proxy metric (`rationale` admits it).

Disposition: values are JUDGMENT; the audit does **not** propose auto-rewriting them.

## SUMMARY

### FACT vs JUDGMENT
- **FACT (mechanically verifiable):** L1, L2, L4, L5, L6, L7(duplication), L9(staleness),
  L11, L12, L13, L14, L15, L16, L17, L18, L19 — **16 findings**.
- **JUDGMENT (needs data or Emil):** L3(coefficients), L7(values), L8, L9(reconciliation),
  L10(deduction magnitudes) — **5 findings**.
- Several are hybrid (a FACT sub-claim + a JUDGMENT sub-claim), split above so each half
  routes correctly.

### Top self-confirming loops (the core risk)
1. **L1/L2 — prediction urgency loop (CONFIRMED, live).** The one unambiguous, code-wired
   loop: a prediction is set to an LLM `urgency` and later "verified" against the LLM
   `urgency`. Quarantined *by label*, still *executing* from two call sites, while its
   sealed authoritative replacement is not wired in. **Highest priority.**
2. **L3 — CORRELATION_MATRIX shape-and-audit loop (declared, partially wired).** The
   score-shaping matrix is the stated foundation for the cross-axis auditor that grades
   those same scores. Not yet closed in code — closing it (the interrupted task) would
   complete a self-confirming loop. **Do not derive the audit rulebook solely from
   CORRELATION_MATRIX.**
3. **L6 — score_generic assertion-laundering.** For 8 axes, the "score" is the upstream
   asserted level re-encoded; honestly tagged `SELF_REPORTED` but not an independent grade.
