**Three commands could not simply be appended to it, for two reasons.** First,
schtasks caps the /TR field at 261 characters and that string is already ~190.
Second and more important, `&&` cannot express "REFUSED is fine": self_forecast.py
exits 2 when it refuses (a cycle is running, or history is shorter than

score before predict, both pairs — and the task now reads:

    cmd /c C:\Users\emilb\Desktop\AGI\CORTEX++_MERGED\tools\prophecy_morning.bat

Every step runs unconditionally and its exit code is judged PER STEP, because
exit 2 does not mean the same thing everywhere: for self_forecast.py (and now
prophecy.py --predict) it is a refusal, announced as a non-failure, but for
scoreboard.py it is ChainBroken — an integrity alarm — and counts as a failure.
Collapsing those would be exactly the silent-degradation defect this repo exists
to catch. The script exits 1 if any step failed, so Task Scheduler's Last Result
stops being 0 and a failure is visible without reading a log.

The dispatcher was tested with probe exit codes BEFORE the live task was touched:
