## Coverage: how it works, and the two traps

Config is a **file**, not flags, because the cycle spawns children and flags never
reach a child. `cov.ini` + `covhelpers/sitecustomize.py`, both committed.

```bat
set COVERAGE_PROCESS_START=C:\Users\emilb\Desktop\AGI\CORTEX++_MERGED\cov.ini
set COVERAGE_ONLY_UNDER=C:\Users\emilb\Desktop\AGI\CORTEX++_MERGED
set PYTHONPATH=C:\Users\emilb\Desktop\AGI\CORTEX++_MERGED\covhelpers
set PYTHONUNBUFFERED=1
venv\Scripts\coverage.exe run --rcfile=cov.ini fast_cycle_runner.py
```

**Trap 1 — the .pth wins.** coverage ships `venv/Lib/site-packages/a1_coverage.pth`,
which starts coverage in EVERY interpreter that sees `COVERAGE_PROCESS_START`, and
`.pth` files run *before* `sitecustomize`. A guard that decides whether to *call*
`process_startup()` decides nothing. `covhelpers/sitecustomize.py` therefore
CANCELS what the .pth started for foreign processes (`stop()` + `erase()`), which
is why `COVERAGE_ONLY_UNDER` must be set. Without it only the parent is measured.

**Trap 2 — a killed parent loses everything.** Coverage has no periodic flush. The
18:44 run reached 14 steps and reported 1.61% over 7 files, because the parent was
killed and only two child data files survived. `sigterm = True` is now in `cov.ini`;
it saves a polite termination, not an OOM kill (SIGKILL is not catchable).

Cleanup is `rm .coverage` and `rm .coverage.*` — **never** `rm .coverage*`, which
also deletes `cov.ini`.

Artifacts from the failed attempts are deliberately NOT named `COVERAGE.json`:
`COVERAGE_REFUSED_1831.json` (45 s, gate refusal) and `COVERAGE_PARTIAL_1844.json`
(killed at 14 steps). The authoritative names stay free until a real run earns them.

**B — the 429 breaker cannot trip.** `core/media_tools.py:248-272`. `is_429()`

`streak = 0`. Alternating 429/403 never reaches `YT_429_TRIP_AFTER = 5`. One run
printed 319 refusals and `memory/yt_backoff.json` does not exist.

The fix: count 403 and 429 together as "refused by YouTube". **Keep** the reset on
an unrelated failure (DNS, disk) — that is correct, and
`test_unrelated_failure_still_resets_the_streak` exists to stop the fix eating it.

Both were held back because a cycle was running: A moves a file the live supervisor
appends to; B changes a module that children spawned later would pick up mid-night.

## The step passport
