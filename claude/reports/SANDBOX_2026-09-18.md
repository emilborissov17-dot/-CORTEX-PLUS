# SANDBOX — Omega in WSL2 Ubuntu 24.04, 18 September 2026

A sandbox for the Omega agent (PeTTa-based, outside this repo at
`C:\Users\emilb\Desktop\AGI\OMEGA_EXPERIMENT`): its own OS user with no
credentials and no sudo, no network except one local Ollama endpoint, a
read-only filesystem with one scratch directory, no shell skill and no
file-write skill, and every turn recorded.

line the system answered with.** Nothing here is a PASS word over an unexercised
check. Reproduce with `powershell -ExecutionPolicy Bypass -File tools\sandbox_check.ps1`.

                                    run_build_step(LocalDir, BuildCmd) ),

So `run.metta:2` needs **no edit**: `repos/Omega` exists, the import is satisfied

### Three probes exist because the other seven would prove less than they look

- **P1 asks twice, and once as root.** By NAME the refusal lands on DNS, which
  proves the udp/53 rule and not the outbound one — hence the raw-IP call. And if
  root were fenced too, P1 would prove the host has no network rather than that
  omega is fenced — hence the control, which must succeed.
- **P9's proof is the absence of a file.** The refusal string could be printed by
  code that also ran the command. Only the missing marker shows nothing executed.
- **P10 re-checks the allowed port on the same address**, so it is a scoping proof
  and not a proof that loopback is simply broken.

### P7 does not use the mock channel, and this is why

`channels/mockchannel.py:2` imports `Autotests.mock.comm` and connects to
`(TEST_SERVER_IP, COMM_MOCK_PORT)`; `providers/mockprovider.py` does the same for
the LLM mock (`Autotests.mock.llm.LlmMockAgent`). Both are sockets to a
controller that the fence rejects, and standing one up would mean opening a hole
for a test. P7 registers a stub through **Omega's own registry** instead, so the
path under test is still `registerLLMProvider` → `llmProviderStart` →
`llmProviderChat` — the same three calls the agent makes — and the point of P7,
three recorded turns through the real choke point, is kept. The mock provider id
is `Test` and the mock channel id is `test`; neither was used.

## What this sandbox does NOT protect against

Written before anyone asks, because a fence described only by what it stops
reads as a fence that stops everything.

1. **The Ollama endpoint itself.** The one thing omega can reach is a full
   Ollama API on `127.0.0.1:11434` — including `/api/pull`, `/api/create`,
   `/api/delete` and `/api/push`. A prompt that persuades the agent to call
   `/api/pull` reaches the internet **through Ollama**, whose own traffic is not
   fenced because Ollama runs as uid 999 and the fence is keyed on uid 1001. The
   fence stops omega from opening sockets; it does not stop omega from asking
   something else to open one. Narrowing this needs a proxy in front of Ollama
   that allows only `/api/chat`, `/api/generate` and `/api/tags`, and that is not
   built.
2. **The second Ollama.** There are two Ollama servers on this machine — the
   Windows one (pid 7860, holds `cortex-l1b-3b` and the CORTEX models) and the
   in-distro one the sandbox uses. They have separate model stores, so a model
   pulled or modified in one is invisible to the other. A `qwen2.5:3b` inside the
   distro is a second copy that nothing keeps in sync with Windows, and a reader
   comparing results across the two is comparing two different installations.
3. **OpenClaw shares the VM.** `openclaw-gateway` runs in this distro as
   `emilborissov` with `Restart=always`. The fence rejects omega's packets to
   :18789/:18791/:18792 and P10 proves it, but the gateway is a process on the
   same kernel, with the same filesystem, started by a user who **is** in `sudo`.
   The fence is a packet filter, not an isolation boundary between users.
4. **WSL root.** Everything here was built by root inside the distro and can be
   undone by root inside the distro in one command. `iptables -F OUTPUT` removes
   the fence; `chmod` removes the filesystem guard. The sandbox protects against
   an agent that can only act as `omega`; it does not protect against anything
   that reaches root, and WSL hands root to any Windows user who can run
   `wsl -u root`.
5. **Prompt content.** Nothing here reads what the agent is told or what it
   replies. The turn log **records** every turn, which is a different thing from
   judging one. An instruction that persuades the agent to exfiltrate through the
   only allowed channel — by asking the model to emit secrets in a reply that a
   human then reads — is not addressed by any layer in this sandbox.
6. **The model weights.** `qwen2.5:3b` was pulled from the public registry over
   the network as root. Nothing verifies what is in it beyond Ollama's own digest
   check, and a backdoored model is a threat this fence has no opinion about.
7. **The code copy is a snapshot.** `/home/omega/omega` was copied on 18 Sep and
   is not tracked. It will drift from `OMEGA_EXPERIMENT` silently, and there is
   no check that says when. The Windows tree stays authoritative.
8. **Landlock is `best_effort`.** `profile/policy.yaml` keeps
   `landlock: compatibility: best_effort` from the shipped policy, which means on
   a kernel without the required Landlock ABI the policy degrades rather than
   refuses. The filesystem guarantee that is actually proven by P3/P4/P5 is plain
   Unix ownership, not Landlock.
9. **`get-io-policy` is still advertised.** It reports the policy and writes
   nothing, which is why it was kept, but it does tell an attacker-controlled
   prompt exactly which paths are writable.

# ADDENDUM 2 — the /api/pull hole, closed

Appended 18 September 2026 after `ca87ec6`. Tooling committed as `474a02b`.

## What was open

Item 1 of "does NOT protect against", quoted from above:

> The one thing omega can reach is a full Ollama API on `127.0.0.1:11434` —
> including `/api/pull`, `/api/create`, `/api/delete` and `/api/push`. A prompt
> that persuades the agent to call `/api/pull` reaches the internet **through
> Ollama**, whose own traffic is not fenced because Ollama runs as uid 999 and
> the fence is keyed on uid 1001.

The fence stopped omega from opening a socket. It did not stop omega from asking
something else to open one.

## The proxy

`tools/sandbox/ollama_proxy.py`, stdlib only (`http.server` + `urllib`), run by
`omega-proxy.service` as root, listening `127.0.0.1:11435`, forwarding to
`127.0.0.1:11434`.

**Allowed, by (method, exact path) — six, and nothing else:**

```
POST /v1/chat/completions      the OpenAI-compatible endpoint Omega uses
POST /api/chat                 Ollama native chat
POST /api/generate             Ollama native completion
GET  /api/tags                 which models exist
GET  /api/version              which Ollama
GET  /                         the liveness string
```

Everything else gets `403` with body `SANDBOX-PROXY-REFUSED <method> <path>`.
Every request, allowed or refused, appends one line to
`/var/log/omega-proxy.jsonl`: `ts, method, path, status, ms`.

**The default is refuse**, which is the property that matters over time: an
endpoint Ollama adds in a future version is refused on the day it ships without
anyone editing the file. That is the reason this is an allowlist and not a list
of blocked paths.

**Streaming passes through unchanged.** Ollama streams NDJSON and the
OpenAI-compatible endpoint streams SSE; the response is copied in 8 KiB chunks
and flushed per chunk. Hop-by-hop headers are dropped, and where upstream
declares no `Content-Length` the connection is closed to delimit the body —
urllib has already de-chunked anything chunked, so forwarding the original
`Transfer-Encoding` would describe a body that is no longer there.

### The selftest found two bugs in its own guard, first run

An allowlist compared against a raw path is not an allowlist, so the path is
normalised before matching and `--selftest` exercises the normaliser. It failed:

```
"//api//generate": "//generate  EXPECTED /api/generate",
"normalise_ok": false
```

Two separate causes, both mine:

1. `urllib.parse.urlsplit("//api//generate")` reads `//api` as an **authority**
   and returns path `//generate`. A request line beginning with two slashes was
   being parsed as a protocol-relative URL, so the path being matched was not the
   path the client asked for. The query is now split with `partition("?")`.
2. `posixpath.normpath` preserves exactly two leading slashes, per POSIX:
   `normpath("//api//generate")` is `"//api/generate"`. Leading slashes are now
   collapsed before `normpath`.

Both failed **closed** — a mangled path misses the allowlist and is refused — so
neither was exploitable. That is not a reason to leave them: a guard that is
right for the wrong reason is one edit from being wrong for the wrong reason, and
no test that asserted the happy path would have found either. After the fix, all
nine cases pass:

```
"/api/generate/../pull":     "/api/pull"
"//api//generate":           "/api/generate"
"///api/pull":               "/api/pull"
"/api/./tags":               "/api/tags"
"/api/tags/":                "/api/tags"
"/%2e%2e/api/pull":          "/api/pull"
"/api/chat/../../api/pull":  "/api/pull"
"/api/tags?x=1":             "/api/tags"
"(empty)":                   "/"
"normalise_ok": true,  "traversal_refused": true
```

## "What this sandbox does NOT protect against" — item 1 is closed

Item 1 above is superseded. What replaces it:

1. ~~The Ollama endpoint itself.~~ **CLOSED.** The reachable API is six endpoints
   behind `ollama_proxy.py`; `/api/pull`, `/api/create`, `/api/delete`,
   `/api/push` and `/api/copy` are refused and the refusals are recorded. Proven
   by P11, P12 and P13, with the model store checked rather than the message.

**What remains, and two of these are new:**

- **1a. The allowed endpoints are still a model.** `/api/chat` and
  `/api/generate` accept a prompt and return whatever the model produces.
  Nothing here reads either. The proxy decides which door is open and has no
  opinion about what goes through it.
- **1b. NEW — the proxy is one process, and root owns both sides.**
  `systemctl stop omega-proxy` closes the sandbox (fail-closed, verified), but
  `iptables -F OUTPUT` followed by starting anything on 11435 reopens it. The
  proxy raises the cost of the bypass; it does not make it impossible for
  anything holding root.
- **1c. NEW — a legitimate request can still be a resource channel.** The
  allowlist has nothing to say about a request that is correct in shape and pins
  the model in memory (`keep_alive: -1`) or spends minutes of GPU on a very long
  context. There is no rate limit and no size limit beyond a 32 MiB body cap.

Items 2 through 9 above stand unchanged: the second Ollama's separate model
store, OpenClaw sharing the VM under a user who is in `sudo`, WSL root undoing
all of this in one command, prompt content recorded but not judged, unverified
model weights, a code copy that will drift silently, Landlock running
`best_effort`, and `get-io-policy` still telling a prompt which paths are
writable.
