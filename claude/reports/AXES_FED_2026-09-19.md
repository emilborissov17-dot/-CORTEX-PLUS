control test matters as much — a genuine single-series feed (NOAA CO2, no

indistinguishable from breaking every working CSV source.

### The four MISSING dates, traced

`ECONOMY_WORK`, `FOOD`, `INFRASTRUCTURE_CITIES`, `MATERIALS_WASTE`. The scorer
records `observation_where: "last_observations"` for all sixteen axes. That file

```
   gbif_count 3692304.0 | kp_index 2.0 | noaa_co2_ppm 432.3

   wb_SH.DYN.MORT 37.4  | wb_SI.POV.DDAY 10.4 | wb_SP.POP.TOTL 8141808945.0
```

**No observation date is stored anywhere in it**, and all four missing-date keys
are *absent* from it entirely. Meanwhile the snapshot's `world_bank` block does
carry `_observed_years`, but keyed by friendly name (`forest_area_pct`), not by
indicator code (`wb_AG.LND.FRST.ZS`), and it has none of the four either.

So the column that carries the real date is the World Bank API's own `date`
field, and **the `wb_<CODE>` ingest path does not record it**. I have not changed
that: it is in `core/global_indicators.py`, it affects every axis rather than
these four, and guessing a date is worse than a MISSING one. The dates stay
MISSING and row 8 counts them apart.

There is also a discrepancy I did not resolve and am not going to paper over: the
scorer reports `observation_where: "last_observations"` for sixteen axes, and
that file holds eight bare values, four of the sixteen keys are absent from it,
and it is 94 days old. Either the field is inaccurate or a second path supplies
the values. Worth one session on its own.
